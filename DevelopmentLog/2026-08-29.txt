Development Log — 2026-08-29
Начало на проекта

Започна разработването на StudentManagement.

Основната цел е постепенно да се изгради система за управление на студенти, като процесът на разработка бъде разбираем и проследим.

Проектът не се разглежда само като приложение, което трябва да работи, а и като възможност да се упражнят реални принципи и практики от software development.

Начална технологична основа

Проектът е създаден с:

ASP.NET Core MVC
C#
.NET 8
Entity Framework Core
SQL Server

Избрана е .NET 8 LTS версия.

В началото не са добавяни излишни технологии или инфраструктура, които не са необходими за основната функционалност.

Целта е първо да се изгради ясна и работеща основа.

Student

Първоначално основната entity е Student.

Започва изграждането на Student функционалността и database слоя.

Database

Създаден е ApplicationDbContext.

Основната връзка е:

Student
   ↓
ApplicationDbContext
   ↓
Entity Framework Core
   ↓
SQL Server


Добавен е DbSet<Student>.

Entity Framework Core

Използван е Entity Framework Core за работа с database.

Започната е работа с migrations и database update.

Целта е database schema да бъде управлявана чрез migration процес, вместо промените да се правят ръчно.

MVC

В началото е използван стандартният MVC подход:

View
  ↓
Controller
  ↓
DbContext
  ↓
Database


На този етап все още няма отделен Service layer.

Начален CRUD

Започва изграждането на основните операции за Student:

Create
Read
Update
Delete

Това е началната работеща функционална основа на проекта.

Development Approach

Проектът се изгражда постепенно.

Вместо всички функционалности да бъдат направени наведнъж, всяка промяна трябва да бъде:

разбрана;
реализирана;
проверена;
след това да се премине към следващата стъпка.
Архитектурна посока

На този ранен етап архитектурата все още е проста.

Предстои да се прецени как да бъдат разделени:

UI;
application logic;
business logic;
data access.

Не се приемат предварително сложни patterns само заради самите patterns.

Основната цел е кодът да остане разбираем и поддържаем.

Историческа бележка

Този ден представлява началото на проекта.

По-късните архитектурни решения не трябва да се пренасят обратно в този запис като че ли са съществували още от самото начало.

Историята трябва да показва как проектът реално се е развивал.
